- 尚未接到界面上的能力必须保留并加以标注，而不是顺手删除。

与之配套的工作边界在阶段开始时即已说清，并在后续各轮授权中保持稳定：

### 2.6 独立差分复核及其结论

t11u 要求以阅读 diff 的方式，把“刚下载、尚未做任何变更的代码”（`main @ aea3f4b`）与当时分支 HEAD（`1d2ee39`）对照，判断客户端体验是否等效无损。方法是对抗性的：不把先前验证门的 40/40 当作证据本身；对搬移的代码使用重命名 / 拷贝检测；对拆分文件按模块拼回后再比较函数体与字符串；提取用户可见文案集合与提示词 / 安全门 / 分类 / 模型参数并做集合或正文对照；并检查存储键、effect 依赖与注册顺序、默认值、事件处理、条件渲染、接口形态、环境加载、中间件顺序、错误处理、CSS 规则与加载顺序、`nowMs` 默认，以及可能改变运行时的类型写法。

主要证据如下：

- 外置 CSS 与原 `<style>` 在去掉空白后，规则正文一致，仅多了一条说明性注释；`index.html` 仍是 Tailwind CDN 在前、自定义样式在后。
- 用户可见文案：两侧各 1604 条不重复的中文 / 粤语短语，集合差为空；英文界面字符串的集合与出现次数也一致。
- `server/gemini` 与 `server/taxonomy` 中的具名函数均可一一对应；`CORE_CHAT_INSTRUCTION`、生活方式 / 快速通道 / 对比 / 图片 / PDA 等提示词块、安全门关键词与 `FULL_ROUTING_CONFIG` 在去掉注释与多余空白后一致；`services/knowledgeBase.ts` 的知识正文字节级一致。`buildChatPrompts` 的唯一源码差异是可选的 `nowMs`：生产路径不传入该参数，`undefined` 仍触发 `formatGlucoseContext` 参数默认值 `Date.now()`，与旧调用 `formatGlucoseContext(glucoseRecords)` 等效。
- 七个静态 `dia_*` 键不变；自动触发键的运行时形态不变。血糖构建仍先处理“既无数値也无症状则静默返回”，再对缺失测量时点弹出「請先選擇「測量時間點」噢！」；负值仍钳制为 0；日期仍按 `zh-HK` 格式化。对话持久化仍剥离图片 base64。重置仍是 `localStorage.clear()`，确认文案未改。
- 环境加载算法、`handleGeminiError` 友好文案、`/api/health` 与 `/api/gemini/*` 的注册顺序、`startServer` 中 Vite / `dist` 分支，均与拆分前一致。
- `useAppLogic` 的持久化 effect 改为在子 hook 内注册，顺序略有前后，但键、值与依赖不变，不构成用户可感知差异。
- `ViewRouter` / `FocusToast` 的条件与文案（「請先點擊一下您想要輸入的空格」）与拆分前一致，包括未接线的 `View.Detail`。

复核结论是：在“核心业务逻辑一致、核心业务文案一致、核心 AI 提示词效果一致”这一标准下，客户端体验等效无损。像素级一致不是本阶段的要求，也不是这次复核的通过条件。复核列出了若干可选加固（例如在 `buildChatPrompts` 内把 `nowMs ?? Date.now()` 写得更直白、为 CSS 资源增加构建期存在性检查），并明确建议不要把问诊自动上报 effect 里原本就不完整的依赖数组当作“无损修复”去改——那会改变一条当前并未被 Chat 界面走到的路径。t13u 决定跳过这些可选项，本阶段不再改代码。

三、核心取舍与设计依据
================================================================================

1. 先有验证网，再拆文件
   若没有可重复对照的基线，大文件拆分很难证明“只是搬移”。因此第一轮先落地 `npm run verify`，后续每一批结构改动都与基线对照。验证门是辅助，不是唯一证据；阶段收口时另做了一次独立的 diff 阅读。

2. 不把 CSS 送进 Vite 打包管线
   首条技术路径看起来更“现代”，但会改写颜色字节并移动链接位置，直接触碰层叠与大字规则的稳定性。最终选择 `public/styles/app.css` 作为不经转换的静态资源，以规则原文不变换取一次额外的静态文件请求。只要该文件随仓库和构建产物一起存在，用户看到的规则与拆分前一致。

3. 不引入 Playwright，不加与本阶段无关的运行时依赖
   交互验证走已有的 Chrome CDP 与 Pillow。`lucide-react` 等暂时未使用的依赖，以及仅被未挂载 `MedicationReminders` 使用的 `motion`，按“未接线能力一并保留”处理，不在本阶段清理。

4. 未接线能力标注后保留
   被明确保留的包括：`DetailView` / `View.Detail` / `View.Result`，未挂载的 `MedicationReminders`，客户端已封装但界面未调用的 `generateDailyTipFromHKWebsites`（以及对应的 `/api/gemini/daily-tip`），以及 `useAppLogic` 中在 `consultStep === 'RESULT'` 时自动上报的 effect（Chat-only 界面不会把步骤设成 RESULT）。它们属于“功能层完整、常规路径不可达”，不是死代码清理对象。

5. 安装默认改为 `npm ci`
   锁文件对齐之后，可重复安装成为默认路径；`npm install` 只作为 `npm ci` 失败时的退路，并需要单独看待锁文件变化。根 README、手动指南与 systemd 文档在文档同步轮达成一致。

6. `nowMs` 只作为可选注入
   它服务于验证金样的可复现性，不改变生产路径的提示词组装。独立复核确认缺省行为与旧代码等价后，不再为“写得更直白”而再改一刀。

7. 问诊自动上报的 effect 依赖保持原样
   该依赖数组在 main 上就是 `[consultStep, result]`。把它“补全”可能改变触发时机，因而不属于无损优化的范围。

8. 《核心业务明细》本阶段不改
   项目主人在文档同步授权中明确：核心业务明细不用改。该文档的临床与存储 / 接口事实经核对仍然成立；CSS 文件位置等工程注记的轻微滞后，按 00 索引情境 5，以代码与手动指南为准，不顺手改写只读业务基石。

9. 代码与文档都只提交在本地
   向 GitHub 推送、打开拉取请求、以及在主人确认收敛之前写入本归档，都不在本阶段已授予的动作之内。t13u 只授权了归档落盘与本地提交。

七、阶段结论与对未来 UI 重构的交接
================================================================================

本阶段在“不改变长者已经看到、已经保存、已经问到的东西”这一前提下，完成了 UI 重构前的工程整理，并用验证门与一次独立的 diff 阅读相互印证：客户端体验在核心业务逻辑、文案与提示词效果上是等效的。代码拆分、领域层、验证网与运行文档已经对齐到当前仓库实况；只读业务基石没有被顺手涂改；历史记忆在获得授权后收入本文件。

收口时的结构，可按“界面可以替换、规则尽量不动”来理解：

- 进程入口仍是根目录 `server.ts`；环境在 `server/env.ts` 加载；路由在 `server/http/`；模型调用与提示词在 `server/gemini/`；安全门与分类在 `server/taxonomy/`。前端仍然只通过 `services/geminiService.ts` 访问同源 `/api/gemini/*`。
- 与界面无关的规则、键名和记录构建在 `domain/`。换皮时，优先复用这些函数与键，而不是在新组件里另写一套 `dia_*` 或另一套血糖校验顺序。
- `hooks/useAppLogic.ts` 仍是页面状态的对外入口；子 hook 在 `hooks/appLogic/`。视图按目录拆分，但业务回传形状与 View 枚举值保持稳定。
- 皮肤与大字规则在 `public/styles/app.css`，由 `index.html` 在 Tailwind CDN 之后引入。若新 UI 仍要承接“默认大字、最小触控高度”等既有决策，需要同时考虑这份静态资源，而不是只复制 Tailwind 类名。
- 验证门 `npm run verify` 可以在未来的界面重构中继续用作回归网：逻辑快照盯契约与提示词组装，DOM 与交互流盯仍被保留的可达路径。金样更新应是有意识的决策，而不是重构过程中的噪音。

对后续 UI 重构，本阶段留下的判断水位可以归纳为：

- 产品与临床的对错，仍以《产品与医学价值北极星.txt》和《本项目剥离UI后用于UI重构的核心业务明细.txt》为准；工程实况以当时的代码、须知与《手动搭建与迭代应用指南.txt》为准。
- 存储键、接口路径、提示词与安全门、环境变量名称，属于对用户与模型都可见的契约，不宜在换皮时悄悄改写。
- 未接线但仍然完整的能力（详情页、结果视图、用药提醒、每日贴士、分步问诊自动上报等）若要删除或改接，宜作为单独的产品决策，而不是重构时的顺便清理。
- 从 AI Studio 取回的导出物，按《仓库纯净性与AI迭代成果回灌实践.txt》处理：`public/styles/app.css`、`domain/`、`scripts/verify/` 等已跟踪路径默认不是删除项；`verify-results/` 不进入仓库。
- 本分支若需出现在远端，等待另一次明确的推送或开具拉取请求的授权。

当前开发服务仍按既有约定停留在 9002。本阶段的代码优化与文档对齐到此收口。
