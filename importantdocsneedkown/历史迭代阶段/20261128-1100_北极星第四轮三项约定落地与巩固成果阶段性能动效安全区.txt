二、巩固成果（每处对应「哪一刻更顺」）
测量方法（自测，非 Lighthouse）：CDP，390×844@2x，CPU 4× 降速，网络 1.6 Mbps / 150 ms，回访用户（已有档案），首页；本地 gzip 静态服务器（与线上同级，基线线上实测 FCP 4.00s / LCP 5.17s 与本地 3.91s / 5.05s 吻合），各 5 次取中位数。
1) 打开 app 的第一屏
   - 分包：首页与首次设定留在入口包；紀錄（含 recharts）、問 AI / 問題（含 react-markdown）、我的 拆成独立 chunk，首屏后空闲时预取。入口 JS 923 kB → 301 kB（gzip 281 → 94 kB）。
   - 已预取的 chunk 同步渲染（不用 React.lazy 的一次性挂起，避免 React 约 300ms 的 fallback 停留）：首次点 tab 的耗时与改前持平（紀錄 155–204 vs 180–272 ms；問 AI 141–185 vs 144–190 ms；再次进入 35–60 ms 不变）。
   - index.html 预载提示（同一批 URL，只是提前开始）：12 个 CSS 分片、Google Fonts CSS（+ preconnect）、首页两张卡片插图。CSS 分片由 1.93s 才开始 → 0.17s 开始；LCP 元素（覆诊卡插图）由 JS 渲染后才发现 → 一开始就下载。
   - 结果（同一会话 A/B 中位数）：FCP 3.89 → 3.20 s；LCP 5.03 → 4.32 s；TBT 800 → 586 ms；CLS 0 → 0。
2) 再次打开
   - public/_headers：/assets/*（内容哈希）一年 immutable；/art/*、/icons/* 一天 + SWR。HTML 与 /styles/*（无哈希）保持默认每次校验。
3) 换 tab 的那一刻：到达动画保留 240ms / --ds-ease，加 12px 方向位移（往右边的 tab 从右进、往左从左进），只用 transform/opacity，不触发重排；ViewStage 在绘制前写 html[data-tab-dir]。prefers-reduced-motion 下无动画（已实测 animation none、按压 transition 0s）。
4) 遮罩淡入改用统一曲线 --ds-ease（原为孤立的 ease-out），与其上的底部表单/对话框同一节奏。
5) 刘海屏：用 CDP 安全区仿真（上 59 / 下 34）发现首页问候与「問題紀錄/我的」右上字号按钮压在状态栏下；已改为从安全区下方开始（普通浏览器 inset 为 0，无变化）。见 p4-safe-before/ 与 p4-safe-after/。
6) 大字模式首页右侧小卡被裁：根因是 1fr 1fr 栅格 + keep-all 长句把列撑宽；改 minmax(0,1fr) 并允许备注换行，同时该卡改为整行。
7) 已检查且无需改动：滚动（我的/紀錄/首页 程序化滚动 p95 帧 17.3–17.5ms，>33ms 帧 0，改前改后一致）；键盘（Layout 已用 visualViewport 推起输入栏）；橡皮筋（canvas overscroll contain、html none）；点击高亮（transparent）；iOS :active（React 根节点已挂 touch 监听）。
