五、iOS Safari 键盘四轮迭代（kb1–kb4）
================================================================================

背景：iPhone Safari 的键盘不改变布局视口，只缩小 visualViewport；聚焦一个输入框时，Safari 还会自行平移页面（offsetTop，下称「平移 P」）以露出光标。桌面 Chrome 不会这样做，所以每轮都写了脚本，用伪造的 visualViewport（高度缩小 + 指定平移 P）在 CDP 里模拟，并以主人的真机测试为最终判断。

kb1（2f615d7，bcae992d）：输入栏跟随 visualViewport
- 做法：输入栏用 transform 随可视视口上移；底栏隐藏时淡出可见；减少动态效果偏好下直接到位。
- 问题：transform 叠加在 Safari 自己的平移之上，平移多少就多出多少空隙，有时还露出底栏。

kb2（fb8f91e + 66b0080，a9fb6a1a）：钉住 body，去掉 transform
- 根因之一：即使 overflow: hidden，iPhone Safari 仍会滚动 document 去露出聚焦的输入框，问 AI 整个框架每次点击上移的量都不同。改为与被仿侧相同的 body position: fixed（fb8f91e）；外壳画布从 R2-10 起已是唯一滚动根，其他内容不随之移动。
- 输入栏改为不用 transform：键盘判定为「可视视口比静止时短」（打开阈值 >100px，保持阈值 >60px），聚焦期间（html[data-kb-chat]）页面滚动容器铺在可视视口上，输入栏 sticky 在其底部；开合各一次 300ms 的 WAAPI 过渡。
- 验证：ios-kb.mjs 在 375×667、390×844、430×932 及放大字下，分别模拟 P=0 与多档平移；改前（ios-kb-before/）多项失败，改后（ios-kb/）全部通过。
- 留下的问题：开合时页面顶部会闪白（cb9185f 说明中记为 a9fb6a1a 的白闪），来源是聚焦期间改动了滚动容器的顶部位置。

kb3（cb9185f，b99ab15b）：对齐被仿侧的 inputViewport，再补上它的空隙
- 只读被仿侧已公开的前端源码（src/services/inputViewport.ts、ChatComposer.tsx，存于 /workspace/northstar-shots/ref-src/），得到其机制：输入框上盖一层「点击即输入」的触控层，静止的点击以 preventScroll 聚焦，Safari 不再平移；以钉住的 body 测量框架，可见高度 = min(框架, vv.height)，遮挡 >120px 视为打开、>1px 保持；页面滚动容器以 240ms cubic-bezier(.4,0,.2,1) 过渡到可见高度，输入栏 sticky 在其底部，底栏让位与淡出用同一曲线；不用 transform、不移动顶部（这正是白闪的来源）；在空白处静止点击会收起键盘。
- 比被仿侧多走一步：滚动容器止于 offsetTop + vv.height，所以 Safari 平移时不再留下空隙（被仿侧会留下与平移等量的空隙）；胶囊离键盘 4px；对话在被跟随时（离底部 <80px）随容器一起上移，稳定后一次平滑对齐；?kbdebug 显示实时视口数值，供真机检查。
- 验证：ios-kb2.mjs 在同一模拟下并排测量模仿侧与被仿侧（ios-kb2/，P=0 与 P=145）。

kb3 补正（cc929c9，c4dc4c3e）：每一次点击都像第一次
- 主人真机反馈：第一次点输入栏正常，第二次点击后出现空隙。
- 根因：触控层在聚焦时就消失，同一次点击剩下的手势落在已聚焦的输入框上，成为一次原生「点光标」，Safari 为露出光标而平移页面。
- 做法：触控层保留到这次点击的手势结束（并取消其合成 click），使用 pointer capture；只在确有对话时才让对话随键盘上移；输入期间若 document 被滚动则复位；kbdebug 记录每次打开的峰值。
- 结果：主人 13:13 测试 c4dc4c3e 后表示满意，并要求把这套机制推广到所有子页面与弹层。

kb4（a18ef41，81b73350）：全应用统一的键盘机制
- 主人 13:13 的要求：所有子页面与弹层的输入都走同一套可复用机制；测试切换输入框、select / 日期、移动光标、长按与无障碍；问 AI 不回退。
- 新文件 components/shell/keyboard.ts，把问 AI 已在真机上验证过的部分抽成共用：
  - isTyping / isTextEntry：哪些元素会弹出键盘，哪些可由触控路径代为聚焦（只限文字类；date / time / select / file 保留原生选择器）；
  - keyboardGeometry：被仿侧的可见高度规则 + 平移补偿（可用区止于 offsetTop + height）；
  - installTapFocus：对未聚焦的文字输入框，静止的短点击以 preventScroll 聚焦；已聚焦的输入框、长按、拖动、双指与非触控输入一律交给浏览器，所以光标移动、选取、滚动、VoiceOver 与外接键盘保持原生；
  - revealField：把聚焦的输入框移进其所在滚动容器的可见部分，并避开上下的固定栏；
  - KEYBOARD_LAYERS：.ds-subpage、.ds-sheet-scrim、.ds-consult-memo-backdrop、.ds-app-dialog-backdrop。
- native.css：这些图层保持完整盒子（键盘滑动时背后不透出），以 padding-bottom: var(--ds-kb-inset) 让出被遮挡的部分，与问 AI 画布同一 240ms 曲线；原先的 bottom: inset 规则被中和，避免两者相加；键盘弹起时去掉 home indicator 的底部留白，「儲存 / 完成」栏直接坐在键盘上；底部表单与备忘弹层的最大高度改以 --ds-kb-visible 为上限，Safari 平移时不再被藏到下方；表单与键盘一起滑动时，两者之间的窄条以表单底色延伸填充。
- autoFocus 换为 focusOnMount（preventScroll），避免挂载时 Safari 平移（LifestyleCard、NextClinicSection、SavedListSection）。
- 键盘配件栏的上一项 / 下一项切换输入框时，可见区与揭示位置随之更新。

子页面 transform 包含块修复（同在 a18ef41）
- 现象：模拟中子页面与底部表单被量成页面大小而不是屏幕大小，底部按钮栏无法坐到键盘上。
- 根因：tab 到达动画使用 fill: both，结束态保留了一个单位矩阵 transform（不是 none）；带 transform 的元素会成为其内部 position: fixed 元素的包含块，于是挂在页面槽里的子页面与弹层被限制在页面范围内。
- 修复：html[data-tab-dir] .ds-view-stage > * { animation-fill-mode: backwards; }，只保留首帧，末帧回到元素自身（opacity 1、无 transform），视觉上没有差别。

kb4 的验证
- ios-kb4.mjs 覆盖问 AI、子页面、底部表单、备忘弹层与对话框中的输入，测试配件栏切换输入框、select / 日期、光标移动、长按与无障碍属性；动画期间以 Animation.setPlaybackRate(0) 冻结再测量与点击，避免点到半途的元素；点击前先 scrollIntoView，避免点到视口外的输入框。
- 结果（r4-regress.txt）：P=0 与 P=145 各 298 项全部通过；问 AI 长对话中胶囊离键盘 4px，最新消息可见，减少动态效果下同样成立。

六、安静的聚焦样式（0e3bc3d，b1336b4d）
================================================================================

- 主人 14:19 的反馈：输入时出现一个很大的绿色聚焦矩形，希望去掉，换成参照被仿侧的克制提示；键盘 Tab 仍要有温和可见的提示；不影响按钮的聚焦。参照方式限定为只看被仿侧的页面与 CSS。
- 盘点的来源：Tailwind ring、:focus-visible 轮廓、浏览器默认 outline、自定义 CSS（含问 AI 胶囊与血糖 / 糖化数值框的 focus-within）。
- 做法（native.css + Layout.tsx + keyboard.ts）：
  - 文字类输入框、textarea、select、问 AI 胶囊、隨手記与血糖 / 糖化数值框在聚焦时只把边框换成柔和的鼠尾草色 --ds-field-focus（#94A991），去掉 ring、光晕与双重框；数值框本身无边框，改用内侧 1px 细线；
  - 键盘 Tab 导航时由 Layout 在 html 上设 data-focus-keys，输入框显示一条聚焦绿 --c-focus 的单线，无光晕；
  - 按钮、chip、卡片等其他控件保留原有 3px :focus-visible 环。
- 验证：focus-shots.mjs 在首页覆诊表单、我的、首次设定、问 AI、问题页、血糖数值、隨手記等处截取「静止 / 点击 / Tab」三态，改前改后并排（/workspace/northstar-shots/focus/before、after 与 compare*.png）；lint / build / verify 通过后发布。
- 结果：主人 14:32 表示「很完美，这一版工作到此结束」。

八、关键决策与理由
================================================================================

- 不用 transform 跟随键盘：transform 会与 Safari 自己的平移叠加，而平移量随每次点击变化；让滚动容器的高度止于可视视口底部，平移与否结果都一致。
- 先对齐被仿侧，再补它的缺口：被仿侧的 inputViewport 已在真机上成立，照搬其判定阈值与 240ms 曲线可以减少猜测；平移补偿与 4px 间距是在此基础上的改进。
- 触控层只代管「静止的短点击、未聚焦、文字类」这一种情况，其他手势全部交给浏览器，以保住光标移动、选取、长按与 VoiceOver 的原生行为。
- 一套机制、一个文件：问 AI 与所有子页面共用 keyboard.ts，以后新增的输入框自动获得同样的行为。
- 聚焦样式只改颜色、不加框：主人认为大块绿框过重，参照被仿侧改为只换边框颜色；键盘用户仍需要清楚的位置提示，所以以 data-focus-keys 区分点击与 Tab 两种来源。
- Tailwind Play CDN 与 Google Fonts 属于依赖层面的决定，本版未改，交由主人另开分支处理（见第十一节）。

十三、经验教训
================================================================================

1. 被仿侧的「开始使用」会创建云端访客帐户
- 被仿侧前端在开始使用时调用后端 POST /auth/guest（见 ref-src/src/services/prototypeOnboarding.ts）。对照截图与键盘对照脚本（capture.mjs、walk.mjs、walk2.mjs、p2-capture.mjs、p2-ref-tabs.mjs、ref-explore2.mjs、ios-kb2.mjs）每次用干净的浏览器资料走过欢迎页，都会在被仿侧的后端创建一个新的访客帐户。这是别人的演示站，留下的帐户不是我们能清理的。主人随后要求不再在被仿侧演示站上创建云端会话；之后的对照（含聚焦样式一轮）只读其公开页面、CSS 与前端源码。
- 可沿用的做法：对照第三方站点时，先读其前端代码，确认哪些操作会写入对方后端，再决定是否用脚本驱动。

2. fill: both 留下的单位矩阵
- 动画结束态的 transform 即使是单位矩阵，也会让元素成为 fixed 子元素的包含块。「看起来没变」不等于「布局上没变」。

3. 根因要在真机现象里找
- kb1 的空隙、kb2 的白闪、第二次点击的空隙，都是真机测试才暴露的；每轮先写能复现该现象的模拟，再修，修后保留脚本作回归。

4. 时间核对
- box 的系统时钟为 UTC。本文的提交、发布时间都已换算为 UTC+8（git log 以 TZ=Asia/Shanghai 显示，wrangler 的 Z 时间加 8 小时）。0230 归档抬头写「约 02:30」，而其提交 9fed842 的时间为 01:32；该归档保持只读未改，以提交时间为准。
