## 0. 文档定位与范围

本文档是 `tangyou_uistan` 在自托管 VM 上的 systemd 托管实例文档。它记录当前实际生效的 unit、运行身份、工作目录、启动命令、日志去向、验收证据与复现路径，供新机器复现与日常运维使用。

覆盖范围：systemd unit、运行用户与主组、工作目录、启动命令、日志路径、健康端点、验收证据、新机器复现清单、运维手册、已知边界。

不覆盖范围：AI Studio 预览环境、上层反向代理/TLS/DNS、应用业务逻辑、密钥值本身。

与通用规范的关系：通用规范提供判据、模板与验收方法；本文档记录本实例的确定值、精确文件、证据与偏差。本文档不重复通用规范的理论解释，必要处只做章节引用。

本文档不记录历史叙事。版本号、验收时间与当前状态标注属于元数据；事故时间线、试错过程与临时 PID 属于另一类文本。

## 3. 配置与密钥

`.env.local` 位于项目根目录：

```
/da04/webser/sour/pro/tangyou_uistan_0/.env.local
```

`server.ts` 启动时的环境变量加载顺序为：

```
进程环境变量 ＞ .env.server.local ＞ .env.local ＞ .env
```

已存在的进程环境变量不会被覆盖。当前 unit 没有设置 `EnvironmentFile=`，应用自行读取 `.env.local`。

## 4. 精确 unit 文件

当前部署副本 `/etc/systemd/system/tangyou_uistan.service` 的全文：

```ini
[Unit]
Description=tangyou_uistan (npm run dev)
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0

[Service]
Type=simple
User=webser
WorkingDirectory=/da04/webser/sour/pro/tangyou_uistan_0
ExecStart=/usr/bin/npm run dev
Restart=always
RestartSec=3
TimeoutStopSec=10
StandardOutput=append:/da04/webser/logs/pro/tangyou_uistan_0.log
StandardError=append:/da04/webser/logs/pro/tangyou_uistan_0.log

[Install]
WantedBy=multi-user.target
```

字段与取舍说明：

| 字段 | 当前选择 | 说明 |
| --- | --- | --- |
| `Description` | `tangyou_uistan (npm run dev)` | 标识服务与运行模式 |
| `After` / `Wants` | `network-online.target` | 网络就绪后启动；弱依赖 |
| `StartLimitIntervalSec` | `0` | 关闭启动频率限制，允许持续重启 |
| `Type` | `simple` | 以 npm 为主进程，启动即视为已启动 |
| `User` | `webser` | 只写用户；主组由 passwd 决定为 `webgp` |
| `WorkingDirectory` | 项目根目录 | 决定相对路径与 `.env.local` 读取位置 |
| `ExecStart` | `/usr/bin/npm run dev` | 绝对路径；无 shell 包裹 |
| `Restart` | `always` | 正常退出与异常退出都会重启 |
| `RestartSec` | `3` | 重启间隔 3 秒 |
| `TimeoutStopSec` | `10` | 停止等待 10 秒，超时升级 SIGKILL |
| `StandardOutput/Error` | `append:` 同一文件 | 应用日志写入文件；未配置轮转 |
| `WantedBy` | `multi-user.target` | 开机自启 |

与通用规范模板的差异：

- 没有显式 `Group=`；主组由 passwd 提供。
- 没有自定义 `Environment=HOME` / `Environment=PATH`；使用 systemd 默认。
- 没有显式 `RequiresMountsFor`；依赖 systemd 对 `WorkingDirectory` 的自动挂载依赖。
- 没有资源限制与沙箱选项；当前处于“推荐档”而非“加固档”。
- 日志使用 `append:` 文件，未使用 journal。

## 5. 安装与启用

新机器上的一种落地顺序：

```bash
# 1. 写入 unit 文件
sudo tee /etc/systemd/system/tangyou_uistan.service > /dev/null <<'EOF'
[Unit]
Description=tangyou_uistan (npm run dev)
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0

[Service]
Type=simple
User=webser
WorkingDirectory=/da04/webser/sour/pro/tangyou_uistan_0
ExecStart=/usr/bin/npm run dev
Restart=always
RestartSec=3
TimeoutStopSec=10
StandardOutput=append:/da04/webser/logs/pro/tangyou_uistan_0.log
StandardError=append:/da04/webser/logs/pro/tangyou_uistan_0.log

[Install]
WantedBy=multi-user.target
EOF

# 2. 静态校验
sudo systemd-analyze verify /etc/systemd/system/tangyou_uistan.service

# 3. 重新加载并启用
sudo systemctl daemon-reload
sudo systemctl enable --now tangyou_uistan

# 4. 首次检查
systemctl status tangyou_uistan --no-pager
curl -sS -m 5 http://127.0.0.1:9002/api/health; echo
```

预期形态：

- `Active: active (running)`
- `Main PID` 为 npm 进程
- `CGroup: /system.slice/tangyou_uistan.service`
- `/api/health` 返回 `"ok":true`、`"configured":true`

## 8. 运维手册

| 操作 | 命令 |
| --- | --- |
| 查看状态 | `systemctl status tangyou_uistan --no-pager` |
| 查看最终配置 | `systemctl cat tangyou_uistan` |
| 查看关键属性 | `systemctl show tangyou_uistan -p ActiveState -p SubState -p MainPID -p Result -p ExecMainStatus` |
| 重启 | `sudo systemctl restart tangyou_uistan` |
| 停止 | `sudo systemctl stop tangyou_uistan` |
| 启动 | `sudo systemctl start tangyou_uistan` |
| 开机自启状态 | `systemctl is-enabled tangyou_uistan` |
| 应用日志 | `tail -f /da04/webser/logs/pro/tangyou_uistan_0.log` |
| unit 生命周期日志 | `sudo journalctl -u tangyou_uistan -f` |
| 端口检查 | `ss -ltnp \| grep 9002` |

代码与依赖变更：

- 前端文件改动由 Vite middleware 热更新，通常不需要重启。
- `server.ts`、`server/*.ts` 等后端改动需要 `sudo systemctl restart tangyou_uistan`。
- 依赖变更后执行 `npm install`，再重启服务。
- 回退时恢复代码或 unit 副本，再 `daemon-reload` 与 `restart`，并按第 6 节重新验收。

手工 `nohup` 方式会与 systemd 争用 9002 端口；当前唯一托管入口是 `tangyou_uistan.service`。pid 文件不再作为服务状态依据，服务状态以 `systemctl` 为准。

## 9. 已知边界与负面清单

| 项 | 当前形态 | 影响与备注 |
| --- | --- | --- |
| 运行模式 | `npm run dev`（Vite middleware） | 常驻 Vite 开发服务器；生产构建未启用 |

| 挂载依赖 | unit 未显式 `RequiresMountsFor` | 依赖 systemd 对 `WorkingDirectory` 的自动挂载依赖 |

| 资源限制 | 未配置 | 无 `MemoryMax`、`CPUQuota`、`TasksMax`、`LimitNOFILE` |
| 沙箱 | 未配置 | 无 `NoNewPrivileges`、`ProtectSystem` 等 |
| `.env.local` 权限 | 未记录精确值 | 复现时需确认权限与属主 |
| 实际 reboot 验证 | 未做 | `is-enabled` 已确认；reboot 验证待补 |
| 迁移后浏览器冒烟 | 未记录 | health 已通过；浏览器端 AI 问答待补 |
| 反向代理/TLS/DNS | 不在本文范围 | 由上层设施负责 |
| AI Studio 预览环境 | 不在本文范围 | 平台托管，与本 unit 无关 |

负面清单：

- 不引入 pm2 或其他 supervisor，避免双重托管。
- 不把 `GEMINI_API_KEY` 写入 unit 文件。
- 不以 root 运行本服务。
- 不在未重新验收的情况下一次性开启全部沙箱选项。
- 不在同一端口上保留第二个手工启动的实例。

## 10. 与通用规范的追溯表

| 本实例的决定 | 通用规范章节 | 理由 |
| --- | --- | --- |
| unit 名与描述 | §5 标准模板 | 标识服务与运行模式 |
| 只写 `User=webser` | §2.1、§4 决策表 | 主组由 passwd 提供；避免组名不存在导致 `216/GROUP` |
| `WorkingDirectory` 指向项目根 | §2.2 | 决定 `.env.local` 与相对路径 |
| `ExecStart` 使用绝对路径 | §2.3 | 不经过 shell 展开；减少信号转发层 |
| `Restart=always` + `StartLimitIntervalSec=0` | §2.4 | 长驻服务持续自愈 |
| `TimeoutStopSec=10` | §2.4 | 控制停止等待 |
| cgroup 位于 `system.slice` | §2.5 | 脱离 SSH 会话生命周期 |
| `append:` 日志文件 | §2.6 | 沿用文件日志；轮转待补 |
| `WantedBy=multi-user.target` | §2.7 | 开机自启 |
| `After/Wants=network-online.target` | §2.8 | 网络就绪后启动 |
| 未配置资源限制与沙箱 | §2.9、§5.2 | 当前处于推荐档；加固档待评估 |
| dev 运行模式 | §4 决策表 | 当前迭代方式；生产构建未切换 |
| 健康端点作为验收项 | §4.2、§7 | 进程存活与业务可用分层 |
| 断连存活验收 | §7 | 验证 cgroup 与会话解耦 |
| 已知边界与负面清单 | §12 | 防止复现时过度工程 |
